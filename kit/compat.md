# Compatibility notes and sources

What the adapters in `adapters/` and `claude/` are based on. All pages were read on **2026-10-22**. Tool docs move fast; if an adapter misbehaves, check the page again first. The status columns live in the matrix in [`README.md`](README.md).

## Decisions and known gaps

- **Ask is not universal.** Claude Code and Cursor can ask the user. Codex and OpenCode cannot, so the adapters block with a message that tells the agent to get the user's confirmation, and the user can run the command themselves. Antigravity documents an `ask` decision, but in a live run (Gemini 3.8 Flash High, Windows, 2026-10-23) a `git push --force` answered with `ask` ran without any prompt, so the Antigravity adapter answers `deny` (`ASK_AS = "deny"`). Set `CODEX_ASK_AS` / `ASK_AS` to `"allow"` if you prefer letting them through.
- **Read guard only where the payload carries enough.** Claude Code's Read tool sends `limit`, so it keeps the big-file rule. Cursor's read hook has no `limit` field, Codex reads files through the shell, and the OpenCode and Antigravity read-tool arguments are not documented, so none of them gets a read guard.
- **Codex and project root.** Codex runs hook commands with the session's working directory. The shipped `hooks.json` uses a path relative to the repo root, so it works when the session starts at the root. Use an absolute path if you start sessions elsewhere.
- **Cursor and Claude hooks at once.** Cursor can import `.claude/settings.json` hooks itself. If both that import and `.cursor/hooks.json` are active, the same command is checked twice (harmless, but you may be asked twice). Keep one.
- **Antigravity deny shape.** Inferred from the field description, but observed working: the same live run showed `tool call denied by pre-tool hook: <reason>` for a denied command. If a version ignores it, change `answer()` in `adapters/antigravity/guard.py` and add the shape to `tests/fixtures/antigravity.json`.
- **Antigravity working directory.** The docs (hooks page, accessed 2026-10-25) do not say where a hook command runs. In the live run a command that named `.agents/hooks/guard.py` failed with a missing file, which points at `.agents/` as the working directory, but that is one observation. The shipped `command` is a one-line Python bootstrap that tries `hooks/guard.py` and `.agents/hooks/guard.py` and runs the first that exists (silent exit 0 if neither does). Both working directories are covered by tests (`tests/test_adapters.py`); the IDE itself was not re-run.
- **Installed layout and `__pycache__`.** Every hook command uses `python -B -I`, so a hook run never writes bytecode into a folder that the overlay or the project tracks.
- **OpenCode on Bun.** The plugin imports `node:child_process`, which Bun provides. The kit test runs it on Node; it has not run on OpenCode's Bun.
- **Not covered:** Roo, Windsurf, Gemini CLI, and anything else. The git hooks, scripts and written rules apply to them unchanged.
