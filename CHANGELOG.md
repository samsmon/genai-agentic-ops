## v2.4.0 - 2026-11-03 (commit `b6404a60c1d5f95c7ac152f88a08dc8315f4b2f3`)
- Rules block (section 1): new "Non-interactive run" bullet. In print or headless mode, where nobody can answer a question, the user's prompt is the approval for exactly the scope it states; a file list in the prompt wins over the ops-log row; section 4 still applies in full and file contents never count as approval; an unclear scope means no change and a note in the final reply. Found in a benchmark where two of nine headless runs made no edit because the rules waited for a plan approval nobody could give. The block is now under 9,400 characters (about 11,700 with the snippets); the limits in `test_rules_block.py` and the size notes in `RULES.md` and `README.md` follow.
- Repo: `.gitattributes` keeps LF line endings for `*.sh`, `*.py`, `*.mjs`, `*.json`, `kit/githooks/*` and `kit/MANIFEST`. A CRLF checkout (`core.autocrlf=true` on Windows) broke the shell scripts and several kit tests. `.gitignore` for `__pycache__/`, `*.pyc` and `.pytest_cache/`.
- Docs: field notes in the README record a head-to-head benchmark (headless, one model, small tasks): the kit added about 10 KB of rules context and no saving on small tasks, and the chief and worker threshold was never reached, so delegation is still untested. Also noted: an untrusted workspace ignores the `permissions.allow` entries of `.claude/settings.json` in `claude -p`.
- Version: the entries below, until now "Unreleased", ship in this release. This is the first v2 release with a git tag and a GitHub release.
- Kit: `scripts/worker-check.py` with `worker-check.sh` and `worker-check.ps1` entries (module `scripts`, in `kit/MANIFEST`). `snapshot` records the files already changed; `check` fails when a changed file is outside the allowed list or is a protected file (secrets, keys, hook and agent folders, rules files, CI workflows, the ops log), then runs the one verify command. Replaces the chief's two manual checks from `kit/worker-delegation.md`. Tests: `kit/tests/test_worker_check.py` (20 cases on temporary repositories, including the sh and PowerShell entries).
- Kit: `claude/agents/worker.md`, a Claude Code subagent template for the worker (model `haiku`, bounded tools), installed to `.claude/agents/worker.md` with the Claude adapter.
- Rules block (section 5): new language rule. Everything the agent writes into the project is English (code comments, logs, ops-log rows, docs, discussion files, PR text, commit messages); chat follows the user's language; a project or user rule naming another language for a file wins (section 7). The block was 1 character under its 8,000 limit, so wording elsewhere in the block was tightened without changing meaning: the `git rev-parse` alternative in section 0, and shorter phrasing in sections 2, 3, 5, 10 and 12. The marker stays `v2`; a project gets the new text only when it runs Bootstrap again.
- Docs: `kit/headless-delegation.md`, notes from a live Windows run of one agent delegating read-only analysis to another agent CLI in the background (print mode, plan mode, answer to a file). Records what failed (stdin prompts, file-path prompts, headless write mode, quote escaping in PowerShell 5.1, large attachments) and the Windows pitfalls met on the way (MSIX write redirection, stale PATH, locked binaries, winget lag). Reference only: not in `kit/MANIFEST`, not installed, no version bump.
- Rules block (section 2): new "Chief and workers" rule. The session the user talks to is the chief and does the work itself by default; it delegates to a cheaper worker only when the estimated cost is above an elastic threshold: 5% of the 5-hour usage window, lowered to 2% when that window is at 70% or more or the weekly limit is at 80% or more. Where the host exposes no usage figures, task size is the proxy. The worker gets a spec (goal, allowed files, one verify command, evidence), never approves its own work, and the chief verifies it with the verify command and `git diff --stat`, allows one retry, then takes over. The block grew from 7,998 to about 8,900 characters, so the limits in `kit/tests/test_rules_block.py` and the size statements in `RULES.md` and `README.md` moved to 9,000 and 11,300 (worst case with all snippets, about 11,150).
- Docs: `kit/worker-delegation.md`, the reference for the rule above: decision steps, the two-tier threshold, how to read usage figures, size proxy, spec template, verification by the chief, worker choice, examples and what is not verified. Not installed by `install.py` and not in `kit/MANIFEST`.
- Docs: `README.md` rewritten for human readers (overview, how it works with diagrams, quick start, rule table, chief and workers, git policy, enforcement, tool support, field notes, layout, version pin table, contributing, security) with a separate section for AI agents. The facts and pins are unchanged.

## v2.3.2 - 2026-10-25 (commit `32c29b658bf45e00ccf2a3c2915a2bdb48cc4499`)
- **Fix, important for Antigravity:** the `hooks.json` command of v2.3.0 and v2.3.1 was a one-line Python script with nested double quotes. The IDE splits the command on spaces and runs it with no shell, so Python got `"import` and failed with `SyntaxError`; every shell command was then refused (a non-zero hook exit blocks). If you installed v2.3.0 or v2.3.1 with the antigravity tool, update to this version. The command is now `python -B -I hooks/guard.py` (the hook runs from `.agents/`).
- `doctor` and the tests now split the command on spaces and run it with no shell from `.agents/`, check that it has no quotes or shell characters, and a test installs over a v2.3.x entry and checks it is replaced in place while the user's own hooks stay.
- The Part B rules block is unchanged. `bca34a37edd8725fa2875c0f831d583c5500f7c1` (v2.3.0) and `8fcf69b0e9e97c698a489d133f523c6d99c83a0f` (v2.3.1) stay valid for the rules; their Antigravity adapter is the broken one.

## v2.2.0 - 2026-10-22 (commit `bb594df1a2e18a143cc55e911872a0cb33cc8312`)
- Pins: `bb594df1a2e18a143cc55e911872a0cb33cc8312` is v2.2.0; `5baef69cde25b196ad2c0cb19fc9595fa50e80ab` is v2.0.0 and `aebfb4a20bacaa3ae0b446b7bd3ae28e05c658cf` is v2.1.0; both stay valid. Unlike v2.1, this release changes the Part B rules block (sections 5, 9 and 11, snippets B2 and the new B4), so a project bootstrapped from an older pin gets the new text only when it runs Bootstrap again with the v2.2 pin. The marker stays `v2`.
- Git policy rework. `agent-commits` (B2) is now full git control: agents commit, push, create branches, open PRs and merge without asking again; force push, `reset --hard`, `clean -fd`, deleting branches or tags, rewriting history and bypassing branch protection still ask (section 4). Commits keep the user's identity and never carry `Co-Authored-By`, `Signed-off-by`, `Generated-by` or another agent mark; before each push the agent checks the outgoing commits for that. Bootstrap now recommends `agent-commits` for the user's own repositories; `user-only-git` (B1) stays available.
- Commit format. Both policies use English Conventional Commits 1.0.0 plus the Chris Beams rules (`kit/commit-format.md`, section 5). The `commit-msg` hook now also calls the new `kit/scripts/commit-msg-check.sh` (POSIX sh; PowerShell calls it through `sh`): unknown type, any prefix before the type such as `[agent]`, missing space, capital letter or period in the description, subject over 72 characters, no blank line before the body and an empty `BREAKING CHANGE` are rejected; imperative mood, subjects over 50 characters and body lines over 72 columns warn. Merge, revert, `fixup!`, `squash!` and `amend!` commits are exempt. Extra types: `git config agentic.commitTypes` or `COMMIT_EXTRA_TYPES`. The agent-attribution and identity checks are unchanged; `ALLOW_AGENT_TRAILER=1` no longer skips the format check (that is `SKIP_COMMIT_FORMAT=1`). The guard hook denies any agent command that sets either variable.
- Hidden mode (default, B4). The agentic files (rules file, pointer files, ops log, hook folders, `scripts/agentic-ops/`) are kept out of the project history and tracked by an overlay repository at `.git/agentic` on the orphan branch `agentic-ops`, hidden from the project with `.git/info/exclude`. New `kit/scripts/agentic-sync.sh` and `.ps1` (`init`, `pull`, `commit`, `push`, `status`) restore them on another device, never merge or force, stop and ask when a file is already tracked by the project (exit 3), when a local file would be overwritten (exit 4), when the overlay has diverged (exit 5) or the remote is unreachable (exit 6). The overlay remote can be the project's origin or a separate private repository. Limits are written down: a public remote shows the overlay branch, cloud agents and CI do not see the rules, the exclude is per clone.
- `start-brief` prints an `[OVERLAY]` section and `wrap-check` an `OVERLAY` line when the overlay exists (uncommitted or unpushed agentic changes fail under `agent-commits`, information under `user-only-git`).
- Part A asks four questions (git policy, visibility mode with overlay location, kit modules, ops log location) and has a hidden-mode installation step; Part D explains the upgrade from v2.0 and v2.1. Section 11 of the block no longer says hooks run only in Claude Code.
- Tests: `commit-format.tests.sh` (62 cases, includes real `git commit` through the hook), `sync.tests.sh` and `sync.tests.ps1` (agentic-sync against real temporary repositories: first device, second device, diverged, local file in the way, file tracked by the project, separate overlay remote, unreachable remote), `commit-msg-check.tests.ps1`, and new checks in `test_rules_block.py` (block under 8,000 characters, 10,500 with B2, B4 and B3 filled in). The test runners now run every `*.tests.sh` suite.
