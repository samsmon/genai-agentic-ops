## v2.2.0 - 2026-10-22 (commit `bb594df1a2e18a143cc55e911872a0cb33cc8312`)
- Pins: `bb594df1a2e18a143cc55e911872a0cb33cc8312` is v2.2.0; `5baef69cde25b196ad2c0cb19fc9595fa50e80ab` is v2.0.0 and `aebfb4a20bacaa3ae0b446b7bd3ae28e05c658cf` is v2.1.0; both stay valid. Unlike v2.1, this release changes the Part B rules block (sections 5, 9 and 11, snippets B2 and the new B4), so a project bootstrapped from an older pin gets the new text only when it runs Bootstrap again with the v2.2 pin. The marker stays `v2`.
- Git policy rework. `agent-commits` (B2) is now full git control: agents commit, push, create branches, open PRs and merge without asking again; force push, `reset --hard`, `clean -fd`, deleting branches or tags, rewriting history and bypassing branch protection still ask (section 4). Commits keep the user's identity and never carry `Co-Authored-By`, `Signed-off-by`, `Generated-by` or another agent mark; before each push the agent checks the outgoing commits for that. Bootstrap now recommends `agent-commits` for the user's own repositories; `user-only-git` (B1) stays available.
- Commit format. Both policies use English Conventional Commits 1.0.0 plus the Chris Beams rules (`kit/commit-format.md`, section 5). The `commit-msg` hook now also calls the new `kit/scripts/commit-msg-check.sh` (POSIX sh; PowerShell calls it through `sh`): unknown type, any prefix before the type such as `[agent]`, missing space, capital letter or period in the description, subject over 72 characters, no blank line before the body and an empty `BREAKING CHANGE` are rejected; imperative mood, subjects over 50 characters and body lines over 72 columns warn. Merge, revert, `fixup!`, `squash!` and `amend!` commits are exempt. Extra types: `git config agentic.commitTypes` or `COMMIT_EXTRA_TYPES`. The agent-attribution and identity checks are unchanged; `ALLOW_AGENT_TRAILER=1` no longer skips the format check (that is `SKIP_COMMIT_FORMAT=1`). The guard hook denies any agent command that sets either variable.
- Hidden mode (default, B4). The agentic files (rules file, pointer files, ops log, hook folders, `scripts/agentic-ops/`) are kept out of the project history and tracked by an overlay repository at `.git/agentic` on the orphan branch `agentic-ops`, hidden from the project with `.git/info/exclude`. New `kit/scripts/agentic-sync.sh` and `.ps1` (`init`, `pull`, `commit`, `push`, `status`) restore them on another device, never merge or force, stop and ask when a file is already tracked by the project (exit 3), when a local file would be overwritten (exit 4), when the overlay has diverged (exit 5) or the remote is unreachable (exit 6). The overlay remote can be the project's origin or a separate private repository. Limits are written down: a public remote shows the overlay branch, cloud agents and CI do not see the rules, the exclude is per clone.
- `start-brief` prints an `[OVERLAY]` section and `wrap-check` an `OVERLAY` line when the overlay exists (uncommitted or unpushed agentic changes fail under `agent-commits`, information under `user-only-git`).
- Part A asks four questions (git policy, visibility mode with overlay location, kit modules, ops log location) and has a hidden-mode installation step; Part D explains the upgrade from v2.0 and v2.1. Section 11 of the block no longer says hooks run only in Claude Code.
- Tests: `commit-format.tests.sh` (62 cases, includes real `git commit` through the hook), `sync.tests.sh` and `sync.tests.ps1` (agentic-sync against real temporary repositories: first device, second device, diverged, local file in the way, file tracked by the project, separate overlay remote, unreachable remote), `commit-msg-check.tests.ps1`, and new checks in `test_rules_block.py` (block under 8,000 characters, 10,500 with B2, B4 and B3 filled in). The test runners now run every `*.tests.sh` suite.

## v2.0.0 - 2026-10-22 (pin: `5baef69cde25b196ad2c0cb19fc9595fa50e80ab`)
- `RULES.md` marker version `v1` -> `v2`. The v1 file and its SHA pin stay valid for projects that remain on v1.
- Bootstrap now asks for a git policy (`user-only-git` or `agent-commits`) and which kit modules to install. Rules block gets sections 9 (git policy, snippet B1/B2), 10 (token discipline), 11 (enforcement, honest about what is text), 12 (harness builder). Optional handoff section 13 (snippet B3).
- Ops log: keep at most 5 finished rows in the main table, rotate older ones to `docs/CURRENT_OPS-archive.md` (not read at session start). Part C adds the archive template. Rule 3 no longer says to commit rows itself; that follows the git policy.
- Harness builder: when work repeats (second occurrence, "every time", a deterministic manual procedure, a recurring mistake) the agent adds one recommendation block to its report instead of building. Declined suggestions go to `docs/HARNESS_DECLINED.md`. Detail in `kit/harness-builder.md`.
- New `kit/`: Claude Code hooks (`guard.py`, `session_start.py`), git hooks (`commit-msg`, `pre-commit`), `start-brief`, `wrap-check`, `precommit-check` in PowerShell and sh, optional `handoff-check`, and tests (PowerShell, Python, bash).
- README: updated rule table, enforcement table, honest field notes for v2.
- Bootstrap handles damaged markers (found by a dry run on a real repo whose `BEGIN` line was missing): END without BEGIN is replaced from the `## Agent Rules` heading to END; BEGIN without END or a bare heading makes the agent stop and ask; no second block is ever appended. Covered by `kit/tests/test_rules_block.py`.
